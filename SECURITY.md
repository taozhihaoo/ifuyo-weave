# SECURITY

> Applies to: **2.0.0-rc.1 (Release Candidate)**

Weave's security baseline and acceptance checklist. M0 established the boundaries and mechanisms; M2.0–M2.15 extended the capability surface. This document has two layers: **"Current Security Boundary" describes the real state of the 2.0 RC**; **"Historical Milestone Specifics" is the acceptance evidence recorded at the time of M0–M8, retained for audit purposes and not a statement of complete 2.0 coverage**.

## Current Security Boundary (2.0.0-rc.1)

### Two Boundary Layers (read this first)

- **UI / Tauri capability layer**: the WebView holds only the registered permissions below — no filesystem, shell, process or http permission. React components cannot touch the filesystem directly.
- **Rust backend layer**: the 2.0 Web / Monitor modules initiate outbound HTTP from Rust via `ureq` (`src-tauri/src/web/fetch.rs:192`, `src-tauri/src/monitor/check.rs`) and **do not go through the Tauri capability system**. Therefore "capabilities grant no network permission" is **not equivalent** to "the application has no network behavior". The constraints on this egress are declared separately below.

### Capability Minimization (registered)

`src-tauri/capabilities/default.json`:

| Permission | Purpose | Registered in |
| --- | --- | --- |
| `core:default` | Events / windows / app metadata | M0 |
| `dialog:default` | User-initiated Open File / Open Folder dialogs (M1 §20); the UI still has no direct fs access | M1 (registered here retroactively) |

Not granted: Tauri plugin permissions for filesystem / shell / process / http / clipboard / notification. M2.x clipboard, capture and notification capabilities are provided by Rust-side crates, not exposed through UI capabilities. Every new permission must be registered with its purpose in this document first.

### CSP

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' ipc: http://ipc.localhost
```

No remote JS / CSS / fonts; `style-src 'unsafe-inline'` exists only for runtime design-token injection. Source: `src-tauri/tauri.conf.json:26`.

### IPC Validation

- All commands are typed (generated by tauri-specta); no `map[string, any]`.
- Every file path input passes through `weave_core::path` first (rejects traversal / reserved names / illegal characters / trailing dots or spaces / relative paths).
- Structured errors (five fields) are returned across IPC; exceptions are not swallowed.

### Network Egress (new in 2.0, explicitly declared)

- **Only** M2.10 Web / M2.11 Monitor make outbound requests, and only when the user explicitly initiates them; all other modules stay in-process with no network calls. Fetching **downloads remote content to the local machine** — it never uploads user files.
- **SSRF denied by default**: the custom `GuardedResolver` classifies targets at the DNS resolution layer as Public / Private / Loopback / LinkLocal / Unknown and rejects local and private networks by default; `allow_private` permits them only when explicitly enabled by the user (`src-tauri/src/web/target.rs:1-7,90-130`, `fetch.rs:186,190`; regression test `target.rs:206`).
- Redirect count / timeout / response body cap / cooperative cancellation are enforced in `fetch.rs`.
- JavaScript-rendered pages and authenticated sessions are not supported (2.1 backlog, stated honestly).

### Prohibitions (applies to all contributors and AI agents in this repository)

- No shell / arbitrary process execution from the UI side
- No telemetry, crash uploads or analytics
- No secrets / tokens / passwords embedded in the repository or logs
- No silent overwrite of user files (M0 wrote no user files; in 2.0 every write-back uses a TOCTOU snapshot + backup + atomic replace + history/undo)
- No expanding capabilities or adding outbound network endpoints without registering them in this document
- No deleting tests to obtain a green build

### Security Test Baseline

Path traversal rejection, invalid parameters and malformed input are covered by the weave-core path contract and command-layer tests; SSRF classification and opt-in have dedicated regression tests; panics are not allowed (workspace-level `unsafe_code = "forbid"` + clippy `-D warnings`). For CI gates see the Quality Gates section of [`README.md`](README.md).

### M7 Batch Engine Specifics (§189)

- Path Safety: input/target directories pass `validate_absolute_path`; Export output name = dest/{source_stem}.{ext} — stem comes from the source filename, ext from a fixed format string, with no user-controlled relative path component and no `..` concatenation surface.
- Symlink: export target existence checks use lstat semantics (exists()); snapshots/revalidation use stat (facts about the link target) — consistent with the existing M1 boundary.
- Overwrite: Never by default (§211); overwriting requires an explicit `overwrite_existing`, and overwritten outputs are marked in History as not automatically undoable (the undo guard must conflict, D58).
- Resource Limits: workers ≤ 8 (IPC clamp); per-item image decoding is guarded by weave-media ImageLimits (same origin as §113 Resource Bomb); the journal is appended line by line, with no memory amplification.
- No Shell / No Arbitrary Code (§153/§154): the Pipeline definition has only six Stage enum variants (serde tag=type) — no script nodes, no command execution surface; unknown stage types are rejected at deserialization.
- Journal Corruption: no panic; the original is isolated and preserved (§197), recovery uses only the intact prefix — there is no "replay on corruption" surface.

### M8 Documents Specifics (§162–§163)

- Path Safety: inputs/outputs pass validate_absolute_path; output naming uses a fixed suffix template ({stem}.{merged|rotated|extract}.pdf / part-NNN) with no user-controlled path component; temp = `.name.weave-tmp-<pid>` in the same directory (controlled, cleanable §127).
- ZIP Safety (§87): entry count / total extracted size / per-entry caps are all validated when the archive is opened; failure = structured rejection.
- XML Safety (§88): quick-xml has no DTD/entity expansion engine — no XXE or entity-expansion surface; external relationships are counted, not fetched (§89, no network).
- PDF Parsing (§162/§163): lopdf pure-Rust parsing; malformed corpus (truncated / garbage bytes / bad XML) tests show no panic; limits (pages/file size) prevent CPU/memory exhaustion; encrypted PDFs are rejected with a structured error (§84).
- Output collision: no overwrite by default (output-first); Merge revalidates for TOCTOU (§141).
- Crash / partial output: temp+promote guarantees the final name always holds a complete artifact (§179).
